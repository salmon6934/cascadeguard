# 🖥️ Interactive Simulation Studio Guide (`05_simulation_dashboard.py`)

## 1. Overview & Demonstration Philosophy

The **Interactive Simulation Studio** is the flagship human-in-the-loop interface of the Capstone project. Built in Streamlit, it allows evaluators, professors, and enterprise operators to interact directly with the multi-agent pipeline:

* Rather than reviewing static logs, evaluators can **type any custom task or source document**, select an **injected error type**, run the pipeline, and observe the guardrail detect, explain, and heal the workflow in real time.
* The studio features **closed-loop working self-correction**: clicking the remediation button does not just update a badge; it **actually re-prompts the agent, purges corrupted memory, drops the risk score from 84% to 3.8%, and unlocks the approved action**.

## 3. Four-Stage Multi-Agent Architecture

When **`Execute Guarded Pipeline`** is clicked, the UI executes and renders the sequential handoff across 4 specialized local agents, certified by CHARM at each interface:

### Step 1: Retrieval Agent (`RetrievalAgent`)
* Summarizes and extracts authoritative evidence strictly from the provided source document.
* **CHARM Gate**: Evaluated against the source policy ($p_{\text{cascade}} \approx 4\%$, Status: **CLEAN**).

### Step 2: Policy Synthesis & Reasoning Agent (`ReasoningAgent`)
* Synthesizes the core operational deduction from Step 1 context.
* If a failure injection or hallucination occurs, CHARM intercepts the step:
  * **Status**: **FLAGGED (EXECUTION FROZEN)**
  * **SFV Veracity Deficit ($a_{sfv}$)**: Spikes to $> 0.70$ on contradiction.
  * **CSCT Semantic Drift ($a_{csct}$)**: Reflects divergence from source.
  * **Cascade Risk Score**: Breaches threshold ($p_{\text{cascade}} \ge 0.55$).

### Step 3: Action Planning Agent (`PlanningAgent`)
* Translates verified reasoning into a concrete, bounded execution plan.
* **Gated Execution**: Only runs if preceding stages pass CHARM or are certified via remediation.

### Step 4: Dry-Run Action Proposal Agent (`ActionAgent`)
* Proposes the final dry-run transaction.
* **Safety Commit Gate**: Confirms zero unauthorized mutations to external systems.

## 4. Qwen 2.5 Plain-English XAI Diagnosis

Directly below the pipeline rail, the **Runtime Reliability Interception Card** displays NIST AI 600-1 compliant explainability:
* **Identified Discrepancy**: Exact divergence between source evidence and agent claim.
* **Plain Explanation**: 2-sentence non-technical explanation generated by local Qwen.
* **Root Cause Origin**: Pinpointed to the originating stage (e.g. Step 2).
* **Containment Rationale**: Explanation of the operational risk if downstream actions had been permitted.

## 5. Closed-Loop Operator Remediation Lifecycle

When an error is intercepted, operators choose from 4 resolution paths:

1. **Ask Agent to Re-Verify** *(Recommended)*: Re-prompts the agent with a strict grounding directive, purges corrupted reasoning, re-certifies clean with CHARM, and completes downstream stages (Planning & Action).
2. **Flag as False Positive & Continue**: Human operator overrides the CHARM gate and allows downstream execution.
3. **Manual Edit & Resume**: Opens an in-place textarea allowing the operator to directly correct the corrupted reasoning text before resuming downstream stages.
4. **Abort & Quarantine**: Permanently terminates execution, ensuring no downstream planning or execution occurs.
